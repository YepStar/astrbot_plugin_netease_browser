# 网易云适配器

独立的 AstrBot 插件。根据对话意图搜索真实歌曲，在网易云站内分享或邀请一起听；QQ 只发送简短告知。另支持歌曲/歌词/评论浏览、公开评论与回复、人设和陪伴状态驱动的自主选曲与实时音频解码。

## 打开面板

AstrBot → 插件 → 网易云适配器 → 页面「music」。面板仅用于登录、收件人绑定、功能开关、活动记录和评论记录。搜索、歌词与评论浏览由 bot 通过后台工具使用，不提供手动浏览页。面板沿用 AstrBot 管理员登录，无额外端口。

1. API 地址填写自建 api-enhanced 服务，Docker 当前可用 `http://ncm-api:3000`。
2. 点击「生成登录二维码」，使用机器人网易云账号扫码并确认，再点击「检查登录并保存」。也可以「验证当前登录」。
3. 填写绑定 QQ 私聊 UMO 和接收分享/邀请的网易云数字 UID，保存到本地。UID 留空不会发送站内消息或接受邀请；不会从联系人列表猜收件人。
4. 自主听歌设置明确的人格 ID；模型 Provider ID 留空时跟随绑定 QQ 会话。开启自主听歌后，以北京时间的活动时段和冷却间隔检查陪伴状态，模型可选择本轮不听。
5. 自主分享、自主邀请和公开评论分别有开关。公开评论默认关闭。

## 行为

- 推荐：意图路由分析需求 → `ncm_search` → 主 Agent 选择返回的真实歌曲 ID → `ncm_share`，歌曲卡片与可选附言发到网易云私信；是否在 QQ 开口由人格语境判断。
- 主动一起听：`ncm_search` → `ncm_invite` 在 QQ 提议 → 用户明确接受 → `ncm_reply_together`，此时才创建真实房间、同步最多 8 首真实候选队列、实时播放，并通过官方客户端使用的原生一起听接口邀请绑定用户，不发送文字链接。无人加入的房间按 TTL 收束。
- 接受邀请：`ncm_join` 或 `/一起听`。只解析绑定网易云用户发来的邀请，旧邀请不重复处理。
- 自主听歌：读取陪伴公开 facade 的结构化当前场景，依据指定人格主动搜索、从真实候选选曲、用 ffmpeg 实时读取解码音频并回写活动。仅按真实消耗时长上报听歌记录；不读取日推、不改日推、不使用日推给用户推荐。
- 模型拿到的是曲目信息、歌词、评论和实际播放回执。解码音频不代表语言模型已获得听觉输入，不能编造音色和乐器听感。
- 私信和评论发送先持久化账本，结果不确定不自动重发；QQ 告知失败不会重发网易云消息。改变收件人、账号服务地址或关闭模块会收束相关活动。
- 网易云小号和你的账号建议互相关注；站内消息可达性、歌曲权限和原生邀请的接收提示仍受网易云账号及客户端限制。

## 邀请失败与重复回复

QQ 提议只是在征求确认，不代表网易云已收到邀请。只有返回 `channel=netease_native_invite,status=sent` 才能确认邀请已发送；尚未建房时不说“点一下就能连上”。工具已经发送的 QQ 文本不在主模型回复中再次复述，也不会再转换成重复语音。

取音源等只读预检失败时，保留本次已确认的歌曲、队列和绑定用户，在提议有效期内由用户新的明确重邀请求触发重试，不自动循环。如果已经开始建房/发送而结果未知，则不重发。网易云 `-460` 属于上游临时风控，不伪装成功；正常授权备用取址同样失败时会如实返回。音源只在内存中按接口有效期缓存，不将 Cookie 或音源 URL 放入模型上下文或活动记录。

## 意图路由接入

使用原生 `@filter.llm_tool`，不依赖指令转换器。提供 `intent_bridge_tool_ready(name) -> bool`，按模块开关、凭据、固定收件人及 ffmpeg 状态报告就绪情况。注册不意味着写操作已成功。

| 工具 | 用途 |
| --- | --- |
| ncm_search(query) | 根据当前意图搜索真实歌曲 |
| ncm_read(song_id) | 读取详情、歌词和评论 |
| ncm_share(song_id,message) | 本轮搜索后站内分享，QQ 告知 |
| ncm_invite(song_id,message) | 本轮搜索后仅在 QQ 提议，等待确认 |
| ncm_reply_together(offer_id,accept) | 确认/拒绝本会话提议；接受后才发送网易云邀请 |
| ncm_room_control(action,reason,song_id) | 同房后切歌、暂停、继续，并由人格语境判断是否表达 |
| ncm_join() | 接受绑定用户已有邀请 |
| ncm_comment(song_id,content,reply_id) | 本轮先浏览后公开评论/回复 |
| ncm_listen(song_id) | 本轮搜索后让机器人自己播放 |
| music_now() / music_room() | 当前歌曲、歌词位置、房间和队列 |

搜索结果只在当前原始事件传递，分享和邀请拒绝模型凭空编的 ID。评论要求本轮先读取目标歌曲。收件人只能来自面板，工具不接受任意 recipient。

意图桥可预执行 `ncm_search`、`ncm_read`、`ncm_join`、`music_now`、`music_room`。分享/邀请依赖搜索结果，由原生主 Agent 继续执行；不要在同一次预分类里猜依赖结果。原指令 `/一起听`、`/听歌状态` 仍可单独在「指令接入」授权，但推荐使用原生工具，避免重复别名。

本机部署时已将上述只读/接受邀请工具加入 `extra_auto_tools`，更新音乐工作流说明，并撤销旧插件指令接入。新插件不直接改意图桥内部执行器。

## 模块边界

- `main.py`：AstrBot 工具、会话权限、生命周期。
- `web.py` 与 `pages/music/`：管理面板与认证后的 API。
- `music/api.py`：网易云 HTTP 适配、凭据隔离、真实歌曲查询。
- `music/service.py`：分享、评论、房间、播放回执。
- `music/player.py`：ffmpeg 实时音频读取解码，不输出服务器扬声器声音。
- `music/autonomy.py`：人设选曲与活动调度。
- `music/companion.py`：可选陪伴 facade 接口；不读取陪伴插件内部文件。
- `music/storage.py`：本地 Cookie、持久化发送账本和活动记录。
- `music/config.py`：统一配置与服务端校验。

需要 Python 3.11+、aiohttp、ffmpeg；本机 AstrBot 容器已有依赖。本机验证的 api-enhanced 版本为 4.30.3。音频获取保留正常账号的歌曲权限，不开启解锁服务。

## 验证与升级

在 AstrBot Python 环境执行 `python -m pytest <插件目录>/tests -q`。测试不会发送真实私信或公开评论。另完成本机已登录 API 的搜索、歌词、评论、房间状态与 3 秒真实音频解码检查。

本地数据位于 AstrBot 的 `data/plugin_data/astrbot_plugin_netease_browser/`，Cookie 不进入配置面板回执、模型提示或 HTTP URL。升级保留此目录和 `data/config/astrbot_plugin_netease_browser_config.json`。

原一起听插件源码已备份后从活动插件目录移出，旧 Cookie 复制到新插件独立数据目录；备份保留在 `data/plugin_data/netease_browser_migration_backups/`。无需重新扫码即可使用当前机器人登录。

## 评论记录

面板「评论记录」显示本插件成功发表的评论与回复，包括歌曲名称/歌手、北京时间和完整评论正文；按发表时间倒序，每页 50 条。评论元数据随执行账本原子保存，重启后保留；结果不确定的发表不会混入成功记录。旧记录没有保存正文时明确显示“旧版本未记录评论正文”，不会补造内容。

## QQ 确认与房间行为（1.1.0）

陪伴 facade 提供真实当前场景，人格音乐调度可选择自己听歌或想和用户一起听。想一起听时仅在 QQ 提议，默认有效 15 分钟；提议及接收用户、歌曲和状态持久化到本地。意图路由通过只读 `intent_bridge_context(event)` 获取本会话待确认提议，理解用户当前的接受/拒绝回答。“等会儿”、疑问、含糊回答不视为接受。接受只授权该歌曲和该接收用户一次；未收到明确接受不能建房或发送站内邀请。

实际发送邀请后，默认 120 秒未进房提醒一次，提醒投递不确定也不重发。等待默认 10 分钟后收束房间。房间轮询按绑定网易云 UID 确认入房；进房后改为最长 60 分钟的活动会话，不再使用等待邀请的超时。以上时间均可在面板调整。

新增“允许一起听切歌、暂停和继续”“同房时允许 bot 自主切歌或暂停”开关。默认每 180 秒至多做一次自主房间决策，通常继续听，只有具体原因才行动；切歌仍必须从真实搜索结果选择。每次操作重新检查同房成员，读回播放命令确认执行后，才在 QQ 自然说明原因。失败/未确认的操作不声称完成，也不自动重试。用户暂停后 bot 不会自行恢复；用户可在 QQ 要求继续。

本地音频解码跟随房间权威播放状态；暂停时停止解码，继续时从真实进度恢复，其他成员切歌也会同步跟随。动作、原因和确认回执保存到执行账本。QQ 主动提议和后续说明同步归档到会话，供后续对话理解。

意图桥只新增通用可选的只读模块状态钩子与音乐工作流说明，沿用会话/插件授权。陪伴插件继续通过已发布 facade 集成，不改其内部状态或调度文件。

## 人格决定是否表达（1.2.0）

分享、切歌、暂停、继续、入房及换歌后的表达，不再固定拼接通知或复述 reason。内部行动动机保留在账本中，是否说出来单独判断：使用配置人格的系统设定、陪伴 facade 的当前场景/情绪/关系、当前私聊与近期对话，以及 LivingMemory 的相关长期记忆，输出 silent / brief / explain。没有随机概率、次数分配、说明冷却或可调说明频率。

LivingMemory 的只读 recall_behavior_context 门面要求原生 QQ 私聊、会话与插件启用、白名单许可、当前人格与目标人格一致；检索固定当前会话和人格，不读取其他人的记忆，不写入任何测试记忆。成功检索但没有相关记忆时，不编造行为偏好；依赖不可用或决策超时时保留已成功动作，并静默降级，不回退固定说明。

表达决策只在本地记录模式和依据，不保存完整检索结果。silent 不发送 QQ 完成通知，也要求主聊天模型不补报内部理由；用户主动追问仍可如实回答。brief 只说自然短句，explain 才展开原因。站内歌曲分享的附言可留空。一起听提议的 QQ 确认和已约定的入房提醒保留。

管理面板不提供说明风格/频率/概率设置，原“换歌时 QQ 告知”开关已移除。“允许 QQ 主动消息”仅作为发送渠道总开关，不决定个性表达。相关其他插件的最小接入补丁见 integrations/。


### 音乐建议与可选记忆读取（1.3.0）

自主选歌前会筛选绑定 QQ 会话中的真实用户音乐建议，同时传给搜索规划和候选选曲。最近对话只读；明确含音乐词的当前消息也会排队，避免在下一次决策前被聊天窗口挤出。仅将音乐原文片段、来源、时间保存到当前 QQ 会话/人格隔离的本地记录，不修改记忆插件原数据。新建议、修改和撤回应优先于旧建议；不强制每首歌曲同一风格。

在音乐面板的「连接与开关 → 音乐建议与记忆」开启 `memory_read_enabled`（默认关闭），选择 `memory_plugin`。当前支持提供 `async recall_behavior_context(*, umo, persona_id, query)` 的已启用记忆插件；LivingMemory 已提供此接口。其他记忆插件会显示未启用或不支持，不会回退读取另一个插件或直接读取其数据库。读取范围受记忆插件自身会话/人格权限约束。该开关同时控制原有音乐表达流程的长期记忆读取。

「音乐建议」页可以手动筛选、查看来源和状态、清空记录。自动筛选在下次自主决策时运行，不改变原有活动时段/频率，不立即开始听歌。关闭记忆读取后，已有记忆建议保留在本地供重新开启时使用，但不会参与选歌；QQ 建议仍可使用。清空后已处理过的来源不会立即重复导入。切换账号会话或人格后使用独立记录。仅筛选成功后标记来源为已处理，网络/模型故障会在下次重试。


### 私聊听歌动作方向（1.3.1）

“推荐你先听《歌名》”“给你推荐一首”按用户给机器人推荐处理：搜索真实候选后用 `ncm_listen` 单独播放，不回发站内分享。“推荐我听”“把歌分享给我”才用 `ncm_share`。长期曲风建议仅记录为选曲参考。意图桥传递本轮语义动作，原生工具执行前再次检查；桥不可用时通过独立语义判断，判断失败不执行播放/分享。支持同一句明确要求先听并分享；否定/假设不授权。搜索回执包含允许的后续工具，误调用分享会返回 `intent_mismatch`，不会发站内消息。


### 连续指定歌曲（1.3.2）

单独听歌未结束时，用户第一次请求另一首，保留当前播放并回复先听完，回执为 `switch_deferred`。该提醒不排队自动播放。之后另一条明确换歌请求才切换；可承接待切歌曲，无须重复歌名。同一消息的重复工具调用不会算第二次。新歌先检查可播放，再中断旧歌；旧歌按实际已消费时长记录 interrupted，并仅在达到30秒时上报，不能标记听完。一起听房间仍走原有房间控制，不被本逻辑打断。


### 原生一起听邀请与自然话术（1.3.3）

QQ 提议只发送模型写的一句自然邀请；没有文案时使用“刚听到《歌名》，想和你一起听会儿。”，不再追加标题、第二次询问或“你答应后再发到网易云”等流程说明。用户在后续消息接受后，才创建房间并发送网易云原生邀请。

原生调用依据本机官方 macOS 网易云音乐 3.1.4 的 resources.pack 静态代码：`app.chunk.62a005a.js` 的 Mc 导出使用 `/api/listen/together/invite/message/send`，`67.chunk.62a005a.js` 的调用参数为 `roomId`、`acceptorId`。插件通过 NCM API 的现有 `/api` 转发入口调用该接口，Cookie 保持在 POST 正文，不复制客户端代码、不伪造私信卡片。失败沿用未知结果/不重试逻辑，不自动改发文字链接。房间状态与收件人权限仍沿用原有检查。

服务端接受邀请不等于接收客户端已显示弹窗。桌面客户端实际提示与加入仍需接收端验证；本次更新没有在未收到新一轮用户接受时主动发送测试邀请。


### 多轮音乐建议（1.3.4）

筛选保留最近对话的上下文，不再将已处理的前一句建议从语境里排除。先说“给你一些歌手名，听他们的热门歌”，后续单发名单，也能关联成音乐建议；名单原文与前文用途分别保留来源。前十分钟内音乐建议的短名单补充会进入候选采集。模型必须提供原文引用，不允许凭空补齐人名。平台身份/时间提醒从筛选上下文剔除。

上下文发生变化才重新筛选；升级后会对仍在近期对话内的旧来源重新关联。清空操作保留已清空来源的排除记录，避免立即重复导入。音乐建议页同时显示主体原文与关联前文。


### 单条编辑与清空确认（1.3.5）

音乐建议页每条记录支持编辑内容与关联说明，保存/取消均在独立弹窗内完成。手动修改标记为人工维护，后续自动筛选不会用同一条原文覆盖它；原始引用单独保留，编辑后的内容参与选曲。保存会核对记录版本和会话/人格，避免覆盖期间发生的新修改。

清空全部建议会先显示确认弹窗，取消或关闭不发出清空请求；后端也要求明确确认与匹配的会话范围。不会操作记忆插件的原始数据。


### 新增和单条删除（1.3.6）

音乐建议页可手动新增建议和关联说明，新增项不依赖记忆读取开关，保存后参与后续自主选歌。单条删除点击后直接执行，不弹确认；清空全部仍保留二次确认。删除会抑制相同来源原文的自动回填，避免下一次筛选又将删除项恢复。新增/删除沿用会话与人格范围检查；单条删除还核对版本，避免删除已更新的内容。


### 一起听进度同步与播放记录（1.3.7）

`playCommand.progress` 是最近一次播放指令的起始位置，不保证随音乐播放增长。轮询重复读到同一指令时，从首次观测的单调时钟锚点估算房间进度，不再因为它仍为 0 而反复重启本地解码。只有真实新指令才参与跳转判定；播放器仍跟随暂停、恢复、换歌和同曲重新播放。面板优先展示本地真实解码进度，缺失时标注来源为指令估计；估计不当作已消费音频或上报听歌时长。

记录分别展示暂停、切歌、同步、离开房间、房间结束和失败。原先留下的 interrupted 记录无法确定具体原因，保留原数据并注明“旧版：本地解码中断，原因未记录”，不改成播放完成。升级需要重载插件，会按既有生命周期结束当前房间，宜在一起听结束后操作。


### 主动邀请与连续歌单（1.4.0）

主动邀请直接说一起听会儿歌，或说出真实歌名；发送边界会将“这首/那首”等未指明代称改为选中歌名。内部选曲理由不直接当作邀请文案，也不声称尚未实际听过的歌“刚听到”。

提议时从真实搜索候选准备最多8首，选中歌曲排第一；搜索不可用或未授权时保留实际可用的较短队列，不伪造歌曲。接受仍需后续新一条用户消息，确认的提议绑定首曲、队列和接收用户。建房同步整份队列，切歌也保留后续曲目，不再替换成单首。

原生客户端已换下一首时跟随客户端；机器人本地确实听完整曲、房间仍在播放原曲时，才按既定队列推进下一首。尊重远端暂停、换歌、入房成员、房间控制开关与会话时限；自动续播不逐首发 QQ 通知，平台写入结果未知不自动重发。达到解码时长上限只算部分播放，不冒充整曲听完来触发下一首。这是根据人设和建议搜索整理的多首歌单，不读取或改变网易云账号日推。
